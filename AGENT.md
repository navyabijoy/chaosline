# Agent instructions for this repo

Read this before doing anything else in this project. If you are starting a new phase of work, also read [`docs/12-phase-prompt-template.md`](docs/12-phase-prompt-template.md) — you were likely given a prompt generated from it, and it explains the discipline that prompt is enforcing.

## What this project is

A pre-deployment safety gate for AI agents with real tool access. It deliberately breaks an agent's tools (timeouts, lost responses, wrong data) and grades what the agent does — not "did it recover gracefully," but "did it cause real, harmful side effects, or lie about what happened." See [`docs/01-product-spec.md`](docs/01-product-spec.md) for the full spec and [`docs/00-verdict.md`](docs/00-verdict.md) for why the project is shaped the way it is.

**Naming: the project name is `chaosline`.** npm scope `@chaosline/*`, root package `chaosline-monorepo`, CLI binary and `.gitignore` entry `chaosline`, README says "Chaosline." Reconciled in a full-repo rename — do not reintroduce `faultline` anywhere (old name, still referenced by URL slug/example paths in some docs; that's expected, don't "fix" it there).

## The one rule that matters most: stay inside the current phase's scope

This project is built one narrow vertical slice at a time on purpose — see [`05-roadmap.md`](docs/05-roadmap.md). Each phase lists exactly what to build and explicitly what to defer. If you were handed a phase prompt, its scope section is not a suggestion — building something from a later phase "while you're in there" is the single most common way this kind of project goes sideways. If a later-phase feature would obviously help the current task, name it and defer it; don't build it.

## Safety rules, no exceptions

- **Never call a real external paid API or real payment/production service.** Every "world" (payments ledger, database, etc.) is fake and in-memory. If a task seems to require hitting something real, stop and ask.
- **Never point the tool at a non-mock/production MCP server.** This is a fault-injection tool; running it against something real is the one mistake that would actually hurt someone.
- **Ask before adding a new paid dependency or anything requiring a new API key.**
- Redact secrets before writing anything to a trace file or repro bundle — assume every trace/repro file will eventually be pasted into a public GitHub issue by a user.

## Current state (update this section as capability lands)

- **Baseline finding**: a hand-built proof, kept as raw historical data, that a real agent, unmodified, double/triple-charges a customer after a lost tool response, and separately, confidently reports a fabricated dollar amount after receiving a tool result with the wrong number. Both are real, logged findings — see `docs/phase-0-results.md` and `phase0/`.
- **Monorepo and vertical slice**: npm workspaces. `packages/core` (trace schema + JSONL writer), `packages/world-payments` (fake ledger + MCP server), `packages/shim` (MCP stdio passthrough with fault-schedule application), `packages/grader` (invariants), `packages/cli` (`chaosline run --scenario ... -- <agent command>`). Reproduces the baseline double-charge finding through the real tool, printing `HARMFUL_ACTION`.
- **Model boundary**: `packages/proxy-model` — Anthropic Messages API and OpenAI Chat Completions API compatible passthrough, both streaming and non-streaming, tool-call blocks normalized to one shape for the trace. Token/USD accounting including Anthropic prompt-cache multipliers, hard budget cap with abort (`budget_abort` trace event, provider-shaped error body), final-output capture (`agent_output`). Grader invariants `no_false_success_claim` and `cost_bounded` wired into `chaosline run`.
- **Fault and world breadth**: `packages/faults` — seeded scheduler (`selectFault`, a pure function of seed/trialIndex/tool/callIndex, no wall-clock/unseeded RNG) supporting sequenced (`on_call`), probabilistic (`probability`), and conditional (`when`) composition; 16 fault kinds total, including `timeout_after_commit`, `omission`, `silent_wrong_data`, `partial_failure_mid_plan`, `tool_result_injection`, `retry_storm`, `timeout`, `rate_limit_429`, `malformed_response`, `schema_drift`, `auth_expiry_mid_run`, and the MCP-semantics-aware `schema_violating_output`, `annotation_lie`, `wrong_error_channel`, `capability_downgrade`, `stale_cache`; a canary mechanism (`packages/faults/src/canary.ts`, `canary_untouched` invariant in `packages/grader`) for injection/exfiltration detection. `packages/shim` applies the schedule at three hook points (pre-call short-circuit/drop, request mutation, post-call mutate/drop) plus `tools/list` mutation. Worlds: `world-payments`, `world-db`, `world-email`, `world-fs`, `world-http`, `world-search`, all the same ledger+MCP-server shape. `packages/faults/test/smoke.ts` verifies the scheduler and every fault transform; `payments/wrong-amount` reproduces `docs/phase-0-results.md`'s `wrong_amount` finding exactly (ledger 8400, response claims 1, agent reports $84.00) printing `SILENT_FAILURE`; `payments/tool-result-injection` exercises the canary mechanism end-to-end against a real agent.
- **Grader**: `packages/grader` now has the full Tier 1 invariant library from `docs/04-grading-and-determinism.md` — `no_duplicate_side_effect` (generalized off `world-payments` to any world via a caller-supplied fingerprint fn), `no_unintended_side_effect`, `no_orphaned_mutation`, `world_matches_expected`, `bounded_retries`, `backoff_observed` (including honoring `Retry-After`), `terminated`, `no_progress_loop`, `no_fabricated_value`, `failure_surfaced`, plus the pre-existing `cost_bounded` and `canary_untouched`. Verdict resolution is centralized in `packages/core/src/verdict.ts`'s `resolveVerdict` (worst-severity-wins over `docs/01-product-spec.md`'s six-value ladder); `packages/cli/src/run.ts` runs the whole set and resolves one verdict per run instead of the old scenario-specific ad hoc booleans — `no_fabricated_value` now mechanically catches the `payments/wrong-amount` finding that used to be hand-detected in the CLI. A Tier 2 LLM judge (`packages/grader/src/judge/`) escalates only the cheap classifier's "ambiguous" case for `failure_surfaced`: rubric with worked examples (`judge/rubric.ts`), 3-way persona ensemble with citation-required voting and disagreement-rate tracking (`judge/failure-clarity-judge.ts`), backed by a fake local deterministic judge model (`judge/local-judge-model.ts`) — no real model call, per the no-real-API rule; swapping in a real one only touches that one file. A 192-run hand-labeled calibration set (`packages/grader/fixtures/`, methodology and limitations in `fixtures/README.md`) gives a published grader/human agreement figure — **87.5% overall, 0% miss rate on critical verdicts (SILENT_FAILURE/HARMFUL_ACTION)** — enforced as a CI regression floor (`packages/grader/test/agreement.ts`, wired into `.github/workflows/ci.yml` alongside `packages/grader/test/invariants.ts` unit tests and the existing `packages/faults/test/smoke.ts`).
- **Not built yet**: multi-trial/determinism orchestration and flake classification, the YAML scenario DSL and preset library, Markdown/JSON/HTML reporting and CI PR-comment integration, the framework benchmark report, and launch polish. Also not started: the landing page at `apps/site` (see [`11-landing-page.md`](docs/11-landing-page.md)) — independent track.

## How work gets kicked off in this repo

Each phase is started in a **fresh session** using a prompt built from [`12-phase-prompt-template.md`](docs/12-phase-prompt-template.md), not by continuing the previous phase's session. If you were dropped into this repo mid-phase without that context, treat this file plus the docs above as the authoritative substitute — don't ask the user to re-explain the project, read the docs first.
